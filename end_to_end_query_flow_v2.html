V2 Agentic Orchestrator: Complete End-to-End Query Trace

Detailed code execution flow for the modular V2 retrieval engine. When configured with QUERY_ENGINE="v2", requests bypass the monolithic legacy route and enter the dependency-injected RetrievalOrchestrator, executing structured intent classification, multi-surface entity resolution, HyDE document expansion, topological task planning, concurrent Neo4j graph traversal, scoped vector search, context assembly with quality gating, and Groq streaming synthesis.

Calls get_semantic_cache().lookup(...). Embeds query using BAAI/bge-small-en-v1.5 and compares against FAISS in-memory index. If a match exists within TTL and matching the active corpus_version:
  1. Yields event: metadata with cached intent and confidence.
  2. Yields event: sources with pre-recorded citations.
  3. Splits cached answer into tokens and yields answer_chunk events.
  4. Yields event: done with cache_hit: true.

Phase 02 • Structured Intent Classification

LLM Intent Classification & Requirements Extraction

IntentClassifier Structured JSON Schema
File Path backend/app/retrieval/intent.py
Class & Method IntentClassifier.classify(effective_query)
Output Schema Pydantic QueryIntent
Renders the query_intent prompt with valid taxonomy paths and executes LLMClient.complete_structured(...). Produces a strongly-typed QueryIntent model containing:
  • query_type: exposure_aggregation | compliance_check | house_view_synthesis | entity_lookup | general
  • entities_mentioned: list of raw entity names in the query
  • taxonomy_paths: validated taxonomy tree branches to constrain vector search
  • requires_graph & requires_vector: booleans deciding routing
  • requires_cypher: detected via aggregation heuristics (sum, count, avg, ranking)
Yields SSE event: metadata to the frontend.

Hypothetical Document Embeddings (HyDE)

HyDE Generator retrieval/hyde.py

Function Name generate_hypothetical_document(effective_query)
If ENABLE_HYDE_IN_ORCHESTRATOR is active and vector search is required, a lightweight LLM pre-pass generates a hypothetical regulatory document passage matching the query intent. This expands the search query: search_query = effective_query + "\n\nHYPOTHETICAL DOCUMENT:\n" + hyde_doc, boosting cosine similarity against real indexed provisions.

Phase 04 & 05 • Concurrent Graph & Vector Retrieval

Parallel Graph Traversal & Scoped Vector Search

Neo4j GraphTraversal VectorStore asyncio.gather
Files retrieval/traversal.py & vector/client.py
Concurrent Execution graph_res, vector_res = await asyncio.gather(_stream_graph(), _stream_vector())
Orchestrator runs both retrieval engines concurrently:
  1. Graph Traversal (Neo4j): Selects strategy based on QueryType (_exposure, _compliance, _house_view, _entity_lookup). Runs parameterised Cypher templates in parallel via _gather_rows().
  2. Vector Search (Qdrant/FAISS): Executes _search_chunks() scoped by intent.taxonomy_paths and resolved_entities.
  3. Emit Sources Event: Immediately formats chunks and yields SSE event: sources to the frontend with document title, ID, score, and snippet.

Phase 07 • Context Assembly & Quality Gate

Context Assembler & Token Quota Manager

ContextAssembler retrieval/context.py
File Path backend/app/retrieval/context.py
Method Name ContextAssembler.assemble(retrieval: RetrievalResult)
Quality Gate Query-Type Aware Threshold (0.10 - 0.50)
Packages graph facts and vector chunks into bounded context:
  • Priority 1: Verified graph facts (capped at graph_fact_quota × token_budget).
  • Priority 2: Pre-computed markdown exposure tables (for exposure queries).
  • Priority 3: Vector chunks ordered by relevance score (capped at vector_quota × token_budget).
  • Quality Gate Evaluation: Calculates quality_score and checks against _QUALITY_THRESHOLDS[query_type].
