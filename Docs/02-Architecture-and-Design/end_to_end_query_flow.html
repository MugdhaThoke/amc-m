Step 04 • Context Memory

Multi-Turn Coreference Resolution

LLM Pre-pass Context Memory
File Path backend/app/engine/context_memory.py
Function Name resolve_coreferences(query, history)
Model Used Groq Light Model (llama-3.1-8b-instant)
If the request contains conversation history, ambiguous references and pronouns (e.g. "Why is their limit higher?", "What about it?") must be resolved into self-contained questions before hitting vector indexes or graphs. The function formats the last 4 turns into a structured prompt and asks the fast LLM to rewrite the query. If no pronouns exist or the query is already explicit, it returns unchanged.

Step 05 • Async Worker Dispatch

Asyncio Queue & Worker Thread Bridging

Backend Concurrency Asyncio.Queue
File Path backend/app/api/routes/chat.py
Function / Closure _chat_stream_generator() -> run_worker()
Mechanism asyncio.create_task(asyncio.to_thread(run_worker))
FastAPI's event loop cannot be blocked by CPU-bound embeddings or synchronous Neo4j queries. _chat_stream_generator creates an asyncio.Queue and passes thread-safe callbacks (on_metadata, on_sources, on_chunk) to run_worker() executing in a background thread. The generator loops on queue.get(), immediately formatting and yielding Server-Sent Event strings.

Step 06 • Retrieval Engine Entry

Intent-Aware Cache Probe (O(1) & Cosine)

Zero-Token Cache Intent Cache
File Path backend/app/engine/retrieval.py & intent_cache.py
Function Name hybrid_graphrag(...) -> icache.fingerprint_probe()
Latency Impact < 5 ms on cache hit
Inside hybrid_graphrag:
  1. Classifies domain intent via classify_domain_intent(query) (e.g. "mutual_fund", "compliance").
  2. Stage 1 (O(1) Fingerprint Probe): Checks SHA-256 normalized hash of the query in memory.
  3. Stage 2 (Vector Semantic Lookup): If fingerprint misses, generates a query embedding and compares cosine similarity against cached questions ($\text{threshold} \ge 0.94$).
On a hit, it emits cached metadata, sources, and streams cached words instantly without touching Neo4j, FAISS, or Groq.

Step 07 • Entity & Query Classification

Dual-Layer NER & Query Type Taxonomy

Information Extraction NER Pipeline
File Paths backend/app/engine/ner_pipeline.py & query_classifier.py
Functions run_layers_ab(query), classify_query(query)
When a cache miss occurs, entity extraction and classification execute:
  • Layer A (Deterministic): Fast Trie / Dictionary matcher checks against known AMC schemes, AMC institutions, regulatory bodies (SEBI, AMFI), and statutory limits.
  • Layer B (Semantic / Regex): Extracts fuzzy scheme names, numerical thresholds, circular numbers, and financial dates.
  • Query Classifier: Categorizes query into "aggregation", "comparison", "direct_lookup", or "general".
Fires metadata_callback to push the first SSE event: metadata to the frontend.

Step 08 • Knowledge Graph Traversal

Neo4j Relational Subgraph Traversal

Neo4j Cypher UNWIND
File Path backend/app/engine/graph_store.py
Function Name get_subgraph_for_query_with_fallback(...)
Pillar Pillar 2: Single-Shot UNWIND Subgraph Traversal
Traverses the knowledge graph in Neo4j using single-shot Cypher queries (avoiding slow iterative N+1 queries): 
MATCH (e:Entity) WHERE e.name IN $entity_names
OPTIONAL MATCH (e)-[r]-(target:Entity)
RETURN e.name AS s, type(r) AS rel, target.name AS o, r.confidence AS conf LIMIT 15
Returns structured triples describing facts like [Kotak Emerging Equity] --HAS_EXPENSE_RATIO--> [1.85%].
Input Entities
entity_names: ["Kotak Emerging Equity Fund"]
hops: 1, limit: 15
Returned Subgraph Result
graph_result: {
  "nodes": ["Kotak Emerging Equity Fund", "1.85%", "1% exit load before 1 year"],
  "edges": [
    {"s": "Kotak Emerging Equity Fund", "rel": "HAS_TER", "o": "1.85%"},
    {"s": "Kotak Emerging Equity Fund", "rel": "HAS_EXIT_LOAD", "o": "1% before 1 yr"}
  ],
  "matched_by": "entity"
}

Step 09 • Vector Retrieval & Reranking

FAISS Parent-Child Search & Cross-Encoder Reranking

FAISS Cross-Encoder
File Path backend/app/engine/faiss_store.py
Function Name FAISSStore.retrieve(query, top_k_children=5, rerank=True)
Models all-MiniLM-L6-v2 (Embedder), ms-marco-MiniLM-L-6-v2 (Reranker)
Retrieves regulatory and document prose chunks through a 3-stage pipeline:
  1. Dense Embedding: Encodes query into a 384-dimensional dense vector.
  2. FAISS Search: Queries index for the nearest child text chunks.
  3. Parent Document Resolution: Looks up parent chunks to ensure surrounding context is not lost.
  4. Cross-Encoder Reranking: Jointly scores (query, passage) pairs with deep cross-attention, returning high-precision ordered hits.
10
Step 10 • Fusion & Vector Gating

Intent-Driven Vector Gating & Context Assembly

Pillars 1 & 3 Context Fusion
File Path backend/app/engine/retrieval.py
Key Logic Score-Gap Sensitive Vector Pruning & RRF Fusion
Applies ContextGraph grounding rules before assembling the LLM prompt:
  • Pillar 1 (Vector Bypass): If Neo4j returned verified structural ground-truth ($\ge 3$ edges) for direct lookup / aggregation, vector search is bypassed to eliminate prose hallucination.
  • Pillar 3 (Strict Vector Gate): If `top1_score - top2_score > 0.10`, lower ranked noisy chunks are pruned from top-5 to top-1.
  • RRF Document Alignment: Vector chunks matching the exact document of cited graph facts receive a $+0.05$ score boost.
  • Emit Sources Event: Fires sources_callback(docs) which sends event: sources to the browser.

Step 11 • LLM Synthesis

Streaming Token Generation via Groq API

Groq LLM Token Stream
File Path backend/app/engine/llm_text_client.py
Function Name stream_llm(system_prompt, user_prompt, model_id)
Model llama-3.3-70b-versatile or llama-3.1-8b-instant
Builds the grounded prompt containing compressed multi-turn history, verified graph facts, and reranked document prose. Invokes the Groq completions endpoint with stream=True. As each token arrives from the Groq API:
  1. Pushes token chunk to stream_callback(chunk, index).
  2. Worker puts ("chunk", {"type": "answer_chunk", "text": chunk, "index": index}) into asyncio.Queue.
  3. Generator formats and yields event: chunk\ndata: {...}\n\n over the HTTP connection.

Step 12 • Audit & Governance

Grounding Validation & Query Evidence Recording

Audit Trail SQLite data.db
File Paths backend/app/engine/retrieval.py & app/retrieval/query_evidence_recorder.py
Functions cross_validate_answer(), record_contextgraph_turn()
After LLM generation completes:
  1. Pillar 5 (Cross-Validation): Evaluates whether numerical claims and entities in the answer are grounded in the retrieved sources, assigning a badge (SUPPORTED / PARTIALLY_SUPPORTED).
  2. Audit Evidence Logging: record_contextgraph_turn writes full forensic telemetry (response ID, query, retrieved triples, vector hits, token count, latencies) to the persistent database.
  3. Cache Indexing: Stores the response in IntentAwareCache.
  4. Pushes event: done frame over SSE with full hybrid telemetry.

React UI AssistantMessage.jsx
