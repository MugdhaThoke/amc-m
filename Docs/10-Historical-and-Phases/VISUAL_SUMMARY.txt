█ THE 6 INITIATIVES AT A GLANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─ 1.1 HyDE Cache ─────────────────────────────────────────────────────────┐
  │ Problem:    Every query regenerates hypothetical doc (50ms LLM call)      │
  │ Solution:   Cache by query prefix; first 30 words → same cache key       │
  │ Impact:     40% queries hit cache → 20ms saved per query on average      │
  │ Risk:       Low (optimization-only, fallback to original on error)        │
  │ Code Lines: ~35                                                          │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 1.2 GLiNER Skip ────────────────────────────────────────────────────────┐
  │ Problem:    GLiNER runs even when Layer A already found entities (15ms)   │
  │ Solution:   Skip GLiNER if Layer A found 2+ confident entities           │
  │ Impact:     60% of queries skip GLiNER → 10ms saved per query            │
  │ Risk:       Low (Layer B is fallback, not primary)                       │
  │ Code Lines: ~25                                                          │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 1.3 Merge Graph Queries ────────────────────────────────────────────────┐
  │ Problem:    Graph queried twice: entity scope, then product scope (90ms)  │
  │ Solution:   Single query with dual-scope UNWIND fallback                 │
  │ Impact:     30% queries with fallback: 40ms saved per query              │
  │ Risk:       Low (same Neo4j logic, just batched)                         │
  │ Code Lines: ~80                                                          │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 1.4 Entity Cache TTL ───────────────────────────────────────────────────┐
  │ Problem:    Entity embeddings cached 5min, re-encoded frequently (20ms)   │
  │ Solution:   Increase TTL to 24 hours (entities change slowly)            │
  │ Impact:     60% cache hit rate on entity resolution → 10ms saved         │
  │ Risk:       Very Low (single config change)                              │
  │ Code Lines: 1 (one line)                                                 │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 2.1 Cypher Correction ──────────────────────────────────────────────────┐
  │ Problem:    15-20% aggregation queries fail, retry with LLM (500ms)      │
  │ Solution:   Rule-based syntax fixes; only LLM retry if needed           │
  │ Impact:     12% of aggregation queries avoid LLM retry → 750ms saved    │
  │ Risk:       Medium (rule-based may miss edge cases, but has fallback)     │
  │ Code Lines: ~250                                                         │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 2.2 Smart Vector Pruning ───────────────────────────────────────────────┐
  │ Problem:    Aggressively prune top-5→top-1, may lose valid context       │
  │ Solution:   Check score gap; keep top-2 if scores within 0.1 points     │
  │ Impact:     10% queries keep more context → quality +2%, no latency      │
  │ Risk:       Low (quality gate, no performance regression)                │
  │ Code Lines: ~20                                                          │
  └──────────────────────────────────────────────────────────────────────────┘

  ┌─ 2.3 Entity FAISS Index ─────────────────────────────────────────────────┐
  │ Problem:    Entity resolution does matrix product on every query (20ms)   │
  │ Solution:   Build FAISS index for entities; O(log N) lookup              │
  │ Impact:     50% matrix products avoided → 15ms saved per query           │
  │ Risk:       Medium (index build at startup, but graceful fallback)        │
  │ Code Lines: ~80                                                          │
  └──────────────────────────────────────────────────────────────────────────┘
