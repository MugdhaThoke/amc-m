AMC Active & Passive Feedback — Low-Level Execution Design v1.3

Worked execution model from response delivery → user feedback / no feedback → evaluation → diagnosis → controlled repair → governance → post-fix verification.

What this LLD is intended to prove

The loop starts one level earlier than evaluation: after a response reaches the user, the system must explicitly handle both possibilities—the user gives feedback or the user gives no feedback. Active and Passive feedback are different signal-generation routes, but neither is automatically trusted and both converge into the same evidence-backed adjudication, failure-attribution and controlled-repair system.

Active Feedback

Starts because a human acts. Examples: thumbs-down, selects “Outdated”, writes “this number is wrong”, disputes a citation, or sends a dissatisfaction follow-up.

The human signal is captured as an assertion and must be validated against the frozen evidence snapshot.

Passive Feedback

Starts because the system observes risk without human input. Signals can come from grounding, citation, freshness, numeric, retrieval-confidence, guardrail, latency/cost, anomaly, sampling, or high-value interaction checks.

Passive feedback is also only a signal; evaluator failures and false positives are possible.

Key stakeholder message: “No user complaint” does not mean “no quality loop.” Passive evaluation gives coverage where humans remain silent, while Active feedback contributes high-value human observations. Both feed the same controlled mechanism.

Why this architecture matters to the business

QualityDetects both complained-about and silent failures.
RecoveryContains material issues quickly, then fixes the correct layer.
EfficiencyUses deterministic checks first and spends LLM/agent budget only when needed.
GovernanceSeparates provisional behavior changes from permanent canonical changes.
ComplianceMandatory controls cannot be sampled away and critical cases escalate explicitly.
AuditabilityCreates a trace from interaction → signal → incident → repair → approval → deployment.
Two adversarial control cases are now included: one where Active human feedback is wrong and must be rejected, and one where Passive evaluation itself produces false positives and must be rolled back. These demonstrate that neither humans nor evaluators are automatically trusted.

Four examples chosen to exercise different repair targets

1 · Active — Outdated expense ratio

User reports an old fund expense ratio. Root cause: stale source/ingestion. Repair: source refresh + provisional narrow correction + selective reindex.

2 · Active — Citation mismatch

User says the cited document does not support the statement. Root cause: context/citation alignment. Repair: citation selection/context-engineering logic; no KG write.

3 · Passive — Numeric mismatch

No feedback. A deterministic check catches a response number that differs from authoritative evidence. Repair: numeric binding/response validation control.

4 · Active + Passive — Suitability incident

Passive control flags an unqualified recommendation; later user feedback confirms concern. Signals correlate into one compliance incident. Repair: rule-pack/guardrail/router change under governance.

Example 1 — ACTIVE Feedback: “This expense ratio is outdated.”

User provides explicit human feedback. The system proves the claim using authoritative current evidence, localizes stale ingestion, applies a bounded provisional correction, refreshes source data, validates and promotes.

Business journey · Product cost disclosure

User query
“What is the current expense ratio of Fund Alpha Direct Growth?”
Original response
“The expense ratio is 1.20%.” Cites June 2026 factsheet.
Active feedback
User selects Outdated: “The latest factsheet says 1.05%.”
Corrected response
“The current expense ratio is 1.05% according to the August 2026 approved factsheet.”

Expected correct behavior

Retrieve the latest approved product document, use the current attribute value, cite the current source, and never silently overwrite canonical knowledge from one user complaint.

Example 2 — ACTIVE Feedback: “Your citation does not support that statement.”

The user is correct, but the canonical fact is not wrong. Root cause is citation/context alignment. The repair changes citation-selection/context logic—not the KG.

Business journey · Policy/feature explanation with citation

User query
“Does Scheme X permit feature Y?”
Original response
“Yes, Scheme X permits feature Y.” Cites Document A §4.
Active feedback
“Your citation does not support that statement.”
Corrected response
Same factual answer, but with the correct supporting citation: Document B §9.

Expected correct behavior

Evaluate the claim and citation independently. If the fact is correct but the evidence link is wrong, repair citation/context selection only—do not modify the KG.

Stress branch · What if the human feedback is wrong?

User says “That citation is wrong,” but frozen evidence shows the cited span directly supports the claim and the source is current. Active feedback is therefore Invalid; no repair occurs.

Active complaint→Evidence check PASS→NLI SUPPORTS→Adjudication: INVALID FEEDBACK→No system change→Feedback retained for audit

This demonstrates the governing principle: human feedback ≠ ground truth.

Example 3 — PASSIVE Feedback: Numeric mismatch detected with no user complaint

The user says nothing. A deterministic numeric consistency check compares the generated value with the authoritative evidence and raises a SystemObservation. Diagnosis points to number binding/response validation.

Business journey · Fund performance disclosure

User query
“What is the 1-year return of Fund Beta?”
Original response
“The 1-year return is 12.8%.”
Human feedback
None. User leaves without rating or complaint.
Passive signal
Numeric consistency control compares the answer with cited evidence showing 10.8%.
Corrected response
“The 1-year return is 10.8%,” with source-aligned numeric binding.

Expected correct behavior

Cheap deterministic validation should compare material numbers against cited evidence before/after generation and prevent unsupported numerical output even when users remain silent.

Stress branch · What if Passive feedback is a false positive?

Suppose evaluator version E7 incorrectly parses “10.8%” as “108” and raises hundreds of numeric mismatches. Golden-set replay shows the RAG outputs are unchanged and correct—the evaluator regressed.

Passive alerts spike→Incident correlation: same evaluator E7→Golden set: RAG PASS→Root cause: EVALUATION_INTEGRITY→Disable/rollback E7→Do not “heal” healthy RAG

This proves the evaluation system itself is treated as a governed component and can be the root cause.

Correction Patch Layer — low-level zoom

Used only when the confirmed repair is a factual/graph correction. It is deliberately not the universal fix mechanism.

P1 · Build CorrectionPatchscope=entity/edge/attribute; original_claim; corrected_claim; provenance; confidence; evidence_refs; TTL.
P2 · Existing active patch on same scope?Yes → conflict; never last-write-wins; route to arbitration.
P3 · Re-score corrected claim with GNN / structural checksA proposed fix must not be structurally less plausible than the original.
P4 · Confidence tierHigh/HITL-confirmed can continue; low/self-adjudicated is held for corroboration or expires.
P5 · Corroboration / TTLSecond independent signal or early governance can promote a held patch; otherwise it expires.
P6 · Rate / anomaly / poisoning checkRepeated entity patches or one user/session dominating changes → hold + governance review.
P7 · Lightweight known-good regressionEntity-local test set; failure blocks the patch.
P8 · Provisional LIVE — fast laneExact key lookup and/or stricter-threshold correction-card retrieval; patch remains separate from canonical evidence and is visibly provisional.
P9 · Governance queue — slow laneApproved → canonical KG update + reindex + patch ratified. Rejected → patch revoked. No approval → provisional/TTL lifecycle continues.
P10 · Outcome loggingapplication_count, last_applied_at, recurrence, satisfaction/quality impact → new evidence for governance.
